ChatGPT 與 Codex 共用用量

之後用 ChatGPT 聊天和用 Codex 寫程式會扣同一個額度，Chat 和 Work 分頁也會先小規模測試合併。

Codex：OpenAI 的程式碼代理工具，可以幫你讀寫專案、跑指令共用額度：兩個服務從同一個用量池扣，一邊用多了另一邊就變少

看更多

Your use of ChatGPT and Codex will draw from the same allowance.

【異動】依 BleepingComputer 11/1 看到的 OpenAI 訂閱者通知信：未來幾週會先找一小群用戶，測試把 Chat 和 Work 兩個分頁合在一起，一般對話就能直接延伸成做網站、做簡報、上網代辦等較複雜任務，不必切換模式；Codex 在 ChatGPT 桌面版仍是獨立介面。【用量】Pro 方案的 ChatGPT 和 Codex 將改吃同一份用量；信中說 Unlimited Instant 包含在訂閱內、不算進共用額度，越進階的模型和越複雜的任務扣越多。剩餘用量和重置時間可在 Settings → Usage 查看；用完可以等重置、升級方案或購買額度。【與上次差別】10/31 本報提過 Pro 100／200／500 的 Work 與 Codex 用量 10/29 起加倍；這次新的是 Chat／Work 合併測試與共用額度。目前只有通知信內容，OpenAI 官方說明頁尚未看到。

Grok API 文字浮水印 11/7 上路

用 Grok API 產生的文字 11/7 起會偷偷帶著看不見的記號，之後能被辨識是 AI 寫的；對一般聊天內容沒有改變。

文字浮水印：生成時微調用字的統計記號，肉眼看不出，但偵測工具能判斷是否為 AI 產生歐盟 AI 法：歐盟的 AI 規範，要求 AI 生成內容要能被機器辨識

看更多

Starting November 7, 2026, responses from these models include a watermark. It's on by default, and you can opt out per model.

【內容】xAI 開發者文件「Output Watermarking」寫明：11/7 起 grok-4.7、4.6、4.5、4.3 和三個 grok-4.20（reasoning／non-reasoning／multi-agent）的文字回覆會預設帶隱形浮水印，套用在所有 API 端點（含全球 api.x.ai 與區域端點），包含一般回覆、結構化輸出和工具呼叫參數。【原理】浮水印是在生成時微調選字，不會多加任何字元或標記；回應的 x-watermark: true 標頭表示該次有加。【原因與關閉】官方說是為了遵守歐盟 AI 法；團隊管理員可在 SpaceXSI Console 逐模型關閉。依 RoboticaGuide 整理，Anthropic 也將把文字浮水印擴大到較舊的 Claude 模型（轉述 The Decoder，未見官方頁）。

來源：xAI 文件：Output Watermarking ↗RoboticaGuide：各家 AI 文字浮水印比較 ↗

Grok Imagine 舊高畫質端點退役

用 API 生圖的人，舊的高畫質模型名稱今天起自動轉到 Image 2.0，格式不用改、還更便宜。

端點／模型名稱（slug）：呼叫 API 時指定要用哪個模型的名字，退役後請求會被轉到別的模型

看更多

On November 2, 2026, grok-imagine-image-quality is retired. Requests to the slug will be served by grok-imagine-image-2.0 with quality set to low.

【異動】xAI API 更新紀錄：11/2 起舊的 grok-imagine-image-quality 模型名稱退役，送到這個名稱的請求會改由 grok-imagine-image-2.0 以 quality=low 處理，請求和回應格式不變、單張價格更低。grok-imagine-image（1.0）不受影響。官方另有遷移指南說明怎麼改用新模型名稱。【對誰有影響】只影響直接呼叫 API 的開發者；在 Grok App 裡生圖的一般用戶不用做任何事。Grok Imagine Image 2.0 目前在 Artificial Analysis 文生圖榜第 6 名（1166 分）。

T8 的 BluePixel 4K 改圖節點

想用一句指令直接改出 4K 圖的人，可以裝 T8 做的 BluePixel 節點，在本地 ComfyUI 跑 vivo 的開源改圖模型。

  • vivo 官方 GitHub README：BluePixel 是以 FLUX.2 Klein 為基礎的原生 4K 改圖模型，不靠另外放大就能輸出 4096×4096，4 步推論（由 50 步教師模型蒸餾），Apache 2.0 授權，權重是 Hugging Face 上的 BluePixel-Turbo。
  • T8 的 Comfyui-BluePixel-T8 節點 README：可在 ComfyUI Manager 搜尋「BluePixel T8」安裝，需 ComfyUI 0.43.0 以上；主模型用 INT8 量化版（9.09GB），加上 Qwen3-8B 文字編碼器和 DCAE-F64 VAE，三個檔案共約 28.19GB 磁碟空間。
  • README 建議從 4 步、CFG 3 開始，附 8 個可直接拖進 ComfyUI 的工作流程（1K 預覽、4K 編輯、多參考圖、保留比例等）；DCAE-F64 不能和一般 Flux2 的 VAE 混用，INT8 是有損量化。
  • 作者說：低顯存下約 8 秒就能採樣一張 4K 圖（影片標題）；README 註明速度、顯存與畫質會隨硬體和任務變化。

蒸餾（Distillation）：用一個大而慢的模型教出一個步數少、速度快的模型INT8 量化：把模型權重壓成 8 位元整數，檔案和顯存變小，但畫質可能略降

Learn
進階 · VRAM 官方文件未標數字；第一次請先用小尺寸測試避免顯存不足（依原頁為準）常青教學

Wan2.2 Animate：讓照片裡的角色照著影片動，或把影片中的人換成你的角色

學會用 ComfyUI 官方 Wan2.2 Animate 工作流程的兩種模式：Move（角色照影片動作動起來）和 Mix（把影片裡的人換成參考圖角色）。

DWPose：從影片偵測人體骨架和臉部表情的工具，產生的動作圖拿來控制角色動作

看更多：步驟
  1. 先更新 ComfyUI，在 Workflow Templates 搜尋「Wan2.2 Animate」載入範本（或下載官方 JSON）。
  2. 下載模型：Wan2.2 Animate 14B（Kijai FP8 版或 BF16 版）放 models/diffusion_models/，lightx2v 4 步加速 LoRA 放 models/loras/，umt5_xxl_fp8 放 models/text_encoders/，clip_vision_h 放 models/clip_visions/，wan_2.1_vae 放 models/vae/。
  3. 用 ComfyUI-Manager 的 Install missing nodes 安裝 ComfyUI-KJNodes 和 comfyui_controlnet_aux 兩個自訂節點。
  4. Mix 模式：上傳參考角色圖和原始影片，DWPose 會自動抽出動作與表情；影片寬高要是 16 的倍數，Points Editor 需先跑一次或手動上傳第一格。
  5. 想要更長的影片就複製「Video Extend」群組，每組多 77 格（約 4.8 秒）；要用 Move 模式照官方說明切換子圖，按 Ctrl+Enter 生成。
教學來源：ComfyUI 官方文件：Wan2.2 Animate ↗Hugging Face：Wan 2.2 ComfyUI Repackaged ↗GitHub：ComfyUI-KJNodes ↗

HiDream-E1.1：用一句話指令改圖（MIT 授權、可商用）

學會在 ComfyUI 跑 HiDream-E1.1 指令式改圖，例如「把背景改成雪景」，不用自己畫遮罩。

指令式改圖（Instruct Editing）：直接用文字告訴模型要怎麼改圖，不需要手動選取範圍

看更多：步驟
  1. 更新 ComfyUI，從 Workflow Templates 或官方頁面載入 HiDream-E1 工作流程。
  2. 下載 hidream_e1_1_bf16（推薦，34.2GB）放 models/diffusion_models/；clip_l_hidream、clip_g_hidream、t5xxl_fp8_e4m3fn_scaled、llama_3.1_8b_instruct_fp8_scaled 放 models/text_encoders/；ae.safetensors（FLUX 的 VAE）放 models/vae/。
  3. 確認模型載入節點的權重類型是 fp8_e4m3fn_fast（省顯存），上傳要改的圖片。
  4. 在提示詞寫修改指令，E1.1 支援約 100 萬像素的動態解析度，按 Queue（Ctrl+Enter）生成。
