Claude Ship：AI 審碼到核准

寫程式的團隊可以讓 Claude 一路包辦「審查 → 修正 → 核准」，例行的小改動不用再等人按核准，但哪些改動要人簽核由團隊自己定。

PR（Pull Request）：把自己改好的程式碼送出、請別人審查後再合併進主程式的請求CI：每次改程式就自動跑測試的流程，紅燈代表有東西壞了

看更多

That's why we built Claude Ship, available today in beta. It can review PRs, fix them, and decide what's ready to merge based on policies each team sets.

【內容】Claude Ship 由三部分組成：已正式上線的 Code Review（多角度審查 PR，可選 Quick／Standard／Deep 三種深度），以及兩個 beta 新代理——PR Steward（處理 CI 失敗、合併衝突和審查意見，每次推送後留言說明改了什麼、怎麼復原；設計上不會核准或合併，留言 @claude stop 可叫它停手）和 Claude Approvals（依團隊寫在 repo 裡的核准政策檔，自動核准例行改動或要求人工簽核，官方形容像更聰明的 CODEOWNERS）。官方建議先用「只觀察」模式建立信心。 【官方數據】Claude Code 團隊 6 月到 9 月合併的 PR 增加一倍以上，被回退的比例下降超過 40%（Claude 審查只是其流程的一層）。 【限制與價格】只支援 GitHub 上的 repo，限 Claude Team 與 Enterprise 方案；依 token 計費，管理員可設 Code Review 與 PR Steward 的花費上限；Approvals 無基本費，但政策中的分類器與觸發的 Code Review 照 token 計費。啟用零資料保留、HIPAA 設定或客戶自管金鑰的組織不能用。

OpenAI × Cisco · 重磅開源2026-11-23

OpenAI 開源 Shirudo 防護盾

發現漏洞後，正式補丁常要等好幾天；Shirudo 讓 AI 先寫一段小程式擋住攻擊路徑，人工核准後直接套上正在跑的系統。

eBPF：可以在 Linux 系統執行中插入小程式、觀察或改變系統行為的技術，不用重開機TPM：電腦裡的安全晶片，能留下不可竄改的紀錄

看更多

OpenAI and Cisco are launching Shirudo, an open-source runtime that helps teams protect Linux systems while they roll out patches.

【怎麼運作】Shirudo（日文「盾」）用 Linux 的 eBPF 技術，在系統執行中觀察可疑行為並套用針對性的防護（shield），只擋住漏洞會用到的程式路徑、正常請求照常通過；代理負責調查漏洞、產生並驗證 shield，由維運人員決定是否部署。shield 會加密簽章、載入前驗證，並用 TPM 硬體記錄每次載入／移除，供事後查核。 【官方實測】受控測試中，用 Codex 產生的 shield 在 Java 的 Base64 解碼器加上輸入檢查，擋下對執行中 Elasticsearch 的 Java4Shell 攻擊，服務不用重啟（屬實驗室測試，非正式環境）。 【限制】GitHub 標示仍是預發布版；正式環境需要帶 signed-loader ABI 與 Shirudo 核心修補的 Linux 核心，以及 TPM 2.0。授權 BSD 2-Clause（BPF 程式另採 BSD／GPL 雙授權）。Cisco 旗下 Isovalent 說明它是 Tetragon 為 AI 代理重寫的版本。

Gemini API 檔案切片

用 Gemini API 處理長文件或長影片時，可以指定只讀第幾頁、哪個儲存格範圍或哪段時間，省錢也讓回答更聚焦。

token：AI 計算文字與圖片份量的單位，API 依 token 數收費

看更多

You can now pass PDFs, Office files (docs, slides, spreadsheets), audio, and video directly to the Gemini API and request only the pages, spreadsheet cells, media segments, and layers you need.

【更新內容】Google AI Studio 與 Gemini 平台的 API 新增伺服器端檔案切片，並原生支援上傳 Microsoft Office 與 OpenDocument 格式。檔案用 Files API 上傳一次即可跨回合重複使用；代理可在 function response 裡自己指定要看哪一段；可以先用文字、低解析預覽或逐字稿粗看，再對重要的圖表或畫面用高解析。 【可調項目】文件／簡報：頁碼範圍、解析度（low／medium／high）、只要文字或頁面影像；試算表：分頁與儲存格範圍、資料／公式／視覺；影片：起訖時間、fps、解析度、逐字稿／畫面／音訊；音訊：起訖時間。 【限制】適用所有 Gemini 4 模型，原本的檔案大小與頁數上限不變。

入門 · VRAM 官方頁未列 VRAM（模型為 8B，範本用 int8 版本，另有更吃記憶體的 BF16 版；依原頁為準）本週新教學

ComfyUI 用 RMBG 3.0 去背：頭髮、玻璃、紗也能留下半透明邊緣

學會下載 RMBG 3.0 的三個模型檔、用官方範本把照片一次輸出成透明背景圖（RGBA）、背景圖和遮罩，並知道去背出錯時該調哪個參數。

Alpha matte（透明度遮罩）：一張灰階圖，白＝保留、黑＝透明、灰＝半透明，讓頭髮等細邊自然RGBA：多了一個透明通道的圖片格式，去背後的圖就是這種

看更多：步驟
  1. 把 ComfyUI 更新到 0.46.0 以上（官方註明範本需要這個版本）。
  2. 在範本庫搜尋「Remove Background: RMBG 3.0」，或從官方頁下載工作流 JSON 拖進 ComfyUI。
  3. 下載模型：rmbg3_int8_convrot.safetensors 放 models/diffusion_models；qwen3vl_4b_int8_convrot.safetensors 放 models/text_encoders；flux2-vae.safetensors 放 models/vae。
  4. 把照片丟進 LoadImage，打開 auto_prompt（範本預設是關的），可在 subject_note 寫一句材質描述，例如「Clear glass bottle, paper label, metal cap」。
  5. 按 Run，結果存在 ComfyUI/output/rmbg3/；cfg 維持 1.0。玻璃或紗變成不透明時，開 auto_prompt、寫材質後把 cfg 提到 1.5～2.0；背景有灰霧就降低 alpha_brightness 或開 hard_mask。
  6. 注意授權：權重是 CC BY-NC 4.0，商用要另外和 Bria 談授權或改用 Bria API。
教學來源：ComfyUI 官方：RMBG 3.0 ↗Hugging Face：briaai/RMBG-3.0-Comfy ↗ComfyUI 官方：更新 ComfyUI ↗
中階 · VRAM 官方頁未列 VRAM（主模型 22B，範本用 fp8 版本，另需 Gemma 12B 文字編碼器；依原頁為準）常青教學

ComfyUI 跑 LTX-2.3：開源影片＋聲音一起生成，從文字或一張圖做出短片

學會從範本庫開 LTX-2.3 文生影片／圖生影片工作流，下載正確的模型檔並放到對的資料夾，做出帶聲音的短影片。

fp8：把模型數字精度壓低到 8 位元的版本，檔案較小、較省顯存FLF2V：給第一張和最後一張圖，讓模型補出中間的動畫

看更多：步驟
  1. 把 ComfyUI 更新到最新版；範本找不到或缺節點，多半是版本太舊。
  2. 到「範本庫 → Video」選 LTX-2.3 的工作流（官方提供文生影片、圖生影片、首尾幀、圖＋音訊對嘴、IC-LoRA 控制、ID-LoRA 六種）。
  3. 依彈窗下載模型，或手動放：ltx-2.3-22b-dev-fp8.safetensors 放 models/checkpoints；distilled 1.1 LoRA 與 gemma abliterated LoRA 放 models/loras；gemma_3_12B_it_fp4_mixed.safetensors 放 models/text_encoders；ltx-2.3-spatial-upscaler-x2-1.1.safetensors 放 models/latent_upscale_models。
  4. 文生影片：改提示詞後按 Run；圖生影片則在 LoadImage 上傳一張圖再寫要怎麼動。
  5. 想要更快可試範本中使用 ltx-2.3-22b-distilled-fp8 的工作流（例如 IC-LoRA 控制）；官方說 9:16 直式影片和聲音品質都比 LTX-2 進步。
