小鵬：AI 讓 L03 10 個月完成

小鵬說 AI 已是外觀、內裝、輪圈、車燈設計的日常工具，並自建內部平台防止未發表設計外流；這次補充了開發時程與 AI 用在哪些「執行面」工作。

客戶診所（Clinic）：車廠找目標客群實際看設計、說喜好與理由的調查場合

看更多

“For exterior design, interior design, wheel design, lamps—it definitely is a tool that we use.”

【誰在做】小鵬創意設計負責人 Rafik Ferrag 在英國 L03 SUV 發表會接受 GoAuto 訪問（11/24 刊出）。 【怎麼用】AI 用於外觀、內裝、輪圈、車燈設計；用自有 AI 工具與內部平台，理由是保護未發表設計、並能掌握輸出結果。工具也協助零件對標（benchmarking）、可行性評估，以及分析大量客戶診所（clinic）回饋，讓團隊在定案前比較更多方案。 【成效】作者說：L03 從白紙需求到量產準備只用 10 個月，AI 是加速工具組的一部分；小鵬未公布每款車省下多少成本。 【作者說】Ferrag 認為未來設計師會像創意總監，指揮多個設計代理；他也承認 AI 可能減少初階設計師的重複視覺化與迭代工作。 【延伸說明】11/17 已報過 CarExpert 的同場訪談；本則新增 10 個月開發時程、零件對標／可行性／診所回饋的用途與成本說法。

零資料保留（ZDR）：服務商不把你送出的提示與回覆存下來

看更多

We've launched Enterprise Frontier Safeguards (EFS) in beta on Claude Platform, Claude Platform on AWS, and Claude Models on Google Cloud (Anthropic managed).

【內容】EFS 是給符合資格組織的零資料保留（ZDR）方案，適用 Claude 最強的模型；Anthropic 不保留提示與回覆，加密副本（Sealed Safety Data）存到客戶自己雲端帳號的 bucket。使用 Anthropic 代管儲存的 workspace 不算 EFS。 【哪裡能用】beta，Claude Platform、Claude Platform on AWS、Google Cloud 上的 Claude Models（Anthropic 代管）。 【附帶更新】組織 webhooks（beta）新增 external_storage.failed／recovered 事件，客戶自管 bucket 每日檢查失敗或恢復時通知。 【退役】Claude Opus 4.5（claude-opus-4-5-20251101、claude-opus-4-5）宣布棄用，Claude API 上 2027-01-22 退役，官方建議改用 Opus 5.5；其他平台日期見 Model deprecations 頁。

Grok Bot 教學與實用資訊

1 則：The Grok Bot Guide 整理 routine 一直失敗的 9 個排查方法。

  1. 2026-11-22

    Routine 失敗的 9 個排查法

    學到：routine 常壞是因為還沒手動跑穩就排程；先在對話裡做對一次、存成技能、寫清楚「要什麼結果」與缺資料時怎麼辦，再用 Test 試跑。

    Routine（例行任務）：讓 Bot 依時間或事件自動重複執行的工作

    看更多

    整理自官方文件與使用者經驗（11/22 更新）：1) 先手動完成一次並修正到對；2) 請 Bot 把做法存成技能（何時用、需要的輸入與權限、步驟、怎麼檢查、回傳什麼、哪些要核准）；3) 寫結果而不是寫死參數（作者引用使用者說法：寫死的 API 呼叫常在第二週壞掉）；4) 建立時確認負責的 Bot、排程與時區（依 Settings → Bot 的時區）、資料來源、預期結果、核准規則、來源缺資料時要回報失敗而非用舊資料；5) 新 routine 要等下一個排程時間才跑，可用 Test 立即試，但 Test 會真的執行；6) 能用連接器就別用瀏覽器（作者引用使用者實測：某任務改用連接器約便宜 45 倍）；7) 留意執行頻率，每次執行都耗用量；8) 網站／連接器／資料格式改變後要重測；9) 沒跑先檢查是否暫停、時區是否正確。文中也提到 1.2.3 版（11/18）起，連接器登入失效的 routine 會跳過排程直到重新登入；每小時上限為全部 routine 300 次、單一 routine 200 次。

ComfyUI 跑 MiniMax H3 Multiframe：用關鍵影格串出續拍與多鏡頭影片

學會用 Add Guide 節點把幾張靜態圖釘在時間軸上（例如 0、1.5、3、5 秒），讓 MiniMax H3 生成的影片依序經過這些畫面，做出接續鏡頭或多鏡頭場景。

關鍵影格（Keyframe）：指定影片在某個時間點一定要長成某張圖的畫面

看更多：步驟
  1. 在範本庫搜尋「MiniMax H3: Multiframe Reference」，或從官方頁下載工作流 JSON 拖進 ComfyUI。
  2. 下載模型：minimax_h3_ref2va_pruned_int8_convrot 放 models/diffusion_models；qwen3vl_32b_minimax_h3_nvfp4_awq 放 models/text_encoders；minimax_h3_video_vae_int8_convrot 與 minimax_h3_audio_vae_fp32 放 models/vae；（選用）4-step turbo LoRA 放 models/loras。
  3. 載入 4 張參考圖：第 1 張同時是身分參考與第一個鏡頭的首格，其餘分別釘在 1.5 秒、3 秒、5 秒。
  4. 每個 Add Guide 的 frame_idx 以 24fps 計算（範本用 round(秒數 × 24) 自動換算，負數代表從片尾倒數），影格位置加長度不能超出影片總長。
  5. 提示詞用 <Picture N> 指名參考圖、寫清楚每個鏡頭在哪個時間點切換；只接在 Add Guide 的圖文字編碼器看不到，要讓提示詞能指到它就同時接到 ref_images。
  6. 想快一點就勾 Lightning LoRA（4 步 turbo），代價是聲音與動作品質略降。
教學來源：ComfyUI 官方：MiniMax H3 Multiframe ↗Hugging Face：Comfy-Org/MiniMax-H3 ↗MiniMax：參考模式提示詞寫法 ↗
入門 · VRAM 官方頁未列 VRAM（8B int8 checkpoint；選用的 PE 文字編碼器檔案 8.82 GB；依原頁為準）本週新教學

ComfyUI 跑 SenseNova U1.6：8B 一體式模型文生圖＋改圖，還會自己檢查重畫

學會下載 SenseNova U1.6 的模型與 8 步 LoRA、在 Turbo（8 步）與 Quality（50 步）之間切換，並用自我修正與提示詞改寫（PE）讓海報、資訊圖的文字更準。

自我修正（Self-Correction）：模型出圖後自己比對提示詞，不符就重畫，最多 5 輪PE（提示詞改寫器）：把一句短提示自動擴寫成完整畫面描述的模型

看更多：步驟
  1. 把 ComfyUI 更新到 0.46.0 以上（官方註明兩個範本都需要）。
  2. 在範本庫搜尋「SenseNova U1.6: Text to Image」或「Image Edit」，或從官方頁下載工作流 JSON。
  3. 下載 sensenova_u1.6_8b_mot_int8_convrot.safetensors（checkpoint）與 sensenova_u1.6_8b_mot_8step_lora_bf16.safetensors（LoRA）；要用 PE 再下載 Qwen Image 2.1 的 PE 文字編碼器（文生圖用 _pe_t2i、改圖用 _pe_i2i）。
  4. 試做時開 Turbo（8 步、CFG 1.0）；要最好的文字與細節就關 Turbo 改 Quality（50 步、CFG 4.0）。預設解析度 4:3、4MP（2368×1760）。
  5. 要出現在圖上的字都用引號括起來；文字多的版面打開 Self-Correction，單純人像就關掉（每多一輪就多跑一次取樣）。
  6. 改圖模式可放 1–4 張參考圖（上限 5 張，越多越吃記憶體）。
